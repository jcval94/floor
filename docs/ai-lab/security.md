# Security and operational boundaries

Trust boundary: operator imports verified snapshots and installs reviewed code. Assistant supplies typed parameters, not code. Question text is stored/escaped and never sent to shell, SQL interpreter, package installer or eval. No arbitrary SQL or shell MCP tool exists. SQL values use bound parameters; schema-profiler identifiers come from sqlite_master and are quoted.

Roles: `read_only` reads only owned runs, shared approved dataset/feature catalogs; `experiment_runner` adds registered submit/cancel/report retries; `research_developer` currently same runtime rights plus off-platform PR preparation; `administrator` adds retention dry-run and cross-owner reads. No role grants production writes, model promotion or trading. Actor/role come from operator environment for local stdio or server-side token-hash mapping for private HTTP, never tool arguments. On a shared host do not give untrusted users access to the volume or ability to set server environment.

HTTP binds **127.0.0.1 only**. Every HTTP request requires a configured bearer identity; only 16 identities, 30 requests/minute per actor. SDK limits body to 64KiB, validates Host/Origin and uses stateless sessions. This private-loopback profile is not a public OAuth 2.1 authorization server. It is suitable only behind an independently approved authenticated tunnel/TLS boundary. Public remote deployment requires approved HTTPS, OAuth metadata/audience/scopes, tunnel/identity compatibility, body/connection limits and a network review. Never pass client GitHub tokens through as MCP credentials. No endpoint was exposed in this work.

Child execution receives only PATH/PYTHONPATH/locale/timezone and private HOME; Slack/GitHub/cloud tokens are omitted. POSIX CPU/address space/file-size/FD limits, process group cancellation and parent-death kill are used. Only reviewed built-in Python recipes run. **This is process isolation, not a hostile-code sandbox or kernel-enforced egress denylist.** Novel/untrusted code execution remains disabled until an approved no-network container or equivalent sandbox is implemented and validated. Resource limits do not substitute for host cgroup quotas, disk quotas and independent volume backups.

Artifacts and MLflow SQLite reside inside the research root, no public URLs. Reports escape untrusted text. Exception messages are reduced to safe codes; provider responses/tokens are never recorded. No raw datasets are sent to Slack. The outbox retains delivery state, API acknowledgement ts, attempt count and safe error code separately from experiment state. Slack timeouts/5xx are ambiguous; marked UNKNOWN for operator reconciliation rather than blind duplicate sends. Exactly-once delivery across network failures is not claimed.

Budgets: only local zero-cloud-cost backend; daily/monthly/actor/storage caps checked atomically before queue acceptance, idempotent replays consume no additional quota. No API to override budget, schedule paid compute or modify environment. Accepted runs retain source/environment/dataset provenance atomically in schema v2, including failures. Worker compares code and dependencies before execution. Full audit of rejected tool requests is not implemented; accepted submit and cancellation records are persisted. TLS termination, OAuth, denial-of-service soak, penetration testing and full transitive dependency locks remain remote-release gates.

Rollback: stop MCP and worker supervisors, retain research volume and export its manifests. Removing `src/ai_lab`, opt-in research tests/docs leaves operational FLOOR unchanged. Do not downgrade a used MLflow schema in place. Restore a copied volume into an empty research root for rollback; never point lab root at `data/` or restore a research DB as official state.
